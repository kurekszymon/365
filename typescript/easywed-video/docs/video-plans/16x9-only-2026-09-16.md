# easywed video plan — 16:9 only · 2026-09-16 · `easywed/v1`

Produced by `/video-plan 16:9` (`365/.claude/skills/video-plan/`), against the product as it exists
at the `easywed/v1` tag and the Remotion project in this repo. Briefs only — nothing here is built.

Scope: **16:9 only** — three landing-page loops and the 60–90 s YouTube walkthrough. The 9:16 and 1:1
formats are out of scope for this run; `full-series-2026-09-11.md` still holds the last plan for
those.

## Strategy

**Who:** a Polish couple with a date, a hall and a guest list, who has already clicked through to
`easywed.app/pl` from a post, an ad or a search. **Where:** on the landing page itself, where a
silent autoplaying loop sits beside *„Wypróbuj bez konta”*, and on YouTube, for the ones who want to
see the whole thing before they touch it. **What action:** press *„Wypróbuj bez konta”* and start a
seating plan in guest mode in this visit. **Why now:** the landing page today shows a static CSS mock
(`PlannerPreview`) — it says what easywed looks like but never shows it doing anything. Each loop
answers one doubt a visitor has *while the button is on screen*: will the tables fit, what if our
room is an odd shape, what happens when someone has to move. The page under the video is the CTA, so
the loops carry none.

## Do not claim

Carried verbatim from the skill, section 4.

- ❌ **Live sync.** There is no Realtime. Collaborators see changes on reload.
  `landing.features.collab.desc` says *"zmiany synchronizują się od razu"* — the landing page
  over-claims this. Do not amplify it.
- ❌ **Plus-ones / "osoby towarzyszące".** No such field on the guest model.
  `landing.features.guests.desc` over-claims this too.
- ❌ RSVP, sending invitations, collecting guest replies.
- ❌ Offline or installable. A manifest exists; there is no service worker.
- ❌ Venue templates, or "import the venue's floor plan". That is manual founder work — a third
  landing over-claim, in `landing.steps.one.desc` (*"lub zaimportuj jej plan"*).
- ❌ A generated PDF *file*. Export opens the browser print dialog (`plan_printed` says as much).
- ❌ Free or included AI. It needs the user's own API key.
- ❌ Reminders that notify. No push, no email, no calendar. It is a dated to-do list.
- ❌ A mobile app. Budget, vendors, timeline, registry, place cards, an auto-seat button. Undo/redo.
- ❌ **Any social proof.** No counts, logos, reviews or testimonials exist, so none may be shown,
  implied, or mocked up.
- ⚠️ Free use covers planning **your own** reception. Planners and venues working commercially need
  the paid plan (`terms.technical.c6`) — so "for wedding planners" framing is off-limits.

### Shared rules for the three loops

- **No CTA card, no *easywed.app* pill.** The page is the CTA.
- **They must loop.** `TransitionSeries` does not wrap last → first, so each loop's final scene ends
  in a 15-frame `LoopSeam`: a crossfade onto scene 1's frame 0, rendered with Remotion's `<Freeze>`.
  Scene 1's frame 0 must therefore be a clean canvas — no hook text yet, no cursor. Built once, in
  `to-scale`, reused by the other two. In the walkthrough the seam is switched off (`loop={false}`).
- **Hook on screen by frame 12**, fully readable by frame 45.
- **Render for the slot, not for 1920.** The hero column is roughly half of `max-w-6xl`; render with
  `--scale=0.5` (960×540) plus a frame-0 still as the `poster`.
- Scene crossfade is the walkthrough's `TRANSITION = 15`: these are page loops, they dissolve.

## Findings

1. **`src/easywed/scenes/GuestsScene.tsx:173` still carries the plus-one over-claim** — *„Diety,
   osoby towarzyszące i przypisane miejsca…”*. It was flagged on 2026-09-11 and is unchanged. Same
   replacement stands: *„Diety, przedziały wieku i przypisane miejsca są zawsze przy nazwisku -
   koniec z trzema arkuszami naraz.”*
2. **The landing page has no 16:9 slot.** The hero's `PlannerPreview` is `aspect-4/3`; the feature
   grid and steps are text columns. Every loop in this plan needs a change in
   `typescript/easywed/src/components/landing/` — the hero slot switched to `aspect-video` (or the
   loop rendered at 4:3, which `useFormat()` would treat as wide and letterbox), plus two full-width
   bands. None of that is in this repo or priced above.
3. **`existing-films.md` is missing on-screen lines.** The walkthrough's `HallScene.tsx:123` subtitle
   (*„Stoły okrągłe i prostokątne, parkiet i wyposażenie - ustaw salę dokładnie tak, jak będzie
   wyglądać w dniu wesela.”*) and `SeatingScene.tsx:64` subtitle (*„Przeciągnij gości na miejsca,
   wyrównaj obłożenie stołów i wyeksportuj gotowy plan do druku dla sali.”*) are on screen but not
   listed as burned. This plan avoids both; the reference file should list them.
4. **`OutroScene.tsx:12` shows *„Eksport PDF do druku”*.** The app's own menu does say *PDF*, but
   the kitchen-report cut deliberately avoided implying a PDF file; the walkthrough outro should
